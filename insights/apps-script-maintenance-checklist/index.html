Google Apps Script 維護前，先確認這些項目

真正的第一步不是立刻改程式，而是確認正在檢查哪個專案、哪個部署與哪份資料。

一、確認資源身分

  • Script ID 與專案名稱是否符合目標。
  • Spreadsheet 是否為正確正式檔案。
  • Web App endpoint 對應哪個 deployment。
  • 測試與正式帳號是否分離。

二、保留唯讀基線

  • 來源檔案與 manifest。
  • 目前部署版本與執行身分。
  • Sheet 表頭、欄位順序與資料列數。
  • Script Properties 使用的 key，不輸出秘密值。
  • 現有觸發器用途與時間。

三、重現問題

記錄錯誤時間、輸入條件、Apps Script 執行紀錄與前端狀態。若無法穩定重現，不應直接在正式資料上試錯。

四、建立回復方式

程式、部署與資料必須分開備份。來源已更新不代表部署已更新；部署更新也不代表 Sheet 資料已改變。

維護時應分開記錄：Source／Project mutation、Deployment mutation、Sheet／business data mutation。

五、最小修改與回歸

測試正常流程、錯誤流程、逾時、重複提交、權限失敗與狀態恢復。核准前不執行正式資料同步或重新部署。
